Case studies

Five systems I designed and own at PayPal — described here at the architecture level, without proprietary code or internal specifics.

AI-powered code review at scale

hours → minutes

1Problem

Manual PR review was a bottleneck — every pull request needed a senior engineer's time, competing with everything else on their plate.

2Approach

Designed and architected an AI-powered Pull Request Analyzer using LLMs to review code, generate contextual comments, flag defects, and recommend improvements before merge.

3Outcome

Cut review effort from hours to minutes. Paired with executive dashboards giving leadership visibility into review quality and adoption org-wide.

GenAI test generation with a governed RAG layer

+80% coverage

1Problem

About 100 features shipped every week, with only one or two days to add tests, so only a handful could be covered. The constraint was scale, not speed.

2Approach

Built a GPT-4-based platform generating tests from a requirement or an OpenAPI spec, with a RAG layer over existing test repositories tagged by language and framework, so output matches each team's conventions. Every generated test is reviewed before merge.

3Outcome

Went from testing a handful of the ~100 weekly features to generated tests for every feature, lifting coverage 80% and cutting manual testing effort 40%.

Two-sided AI quality gates — before and after release

pre + post release

1Problem

Catching quality issues at only one point in the lifecycle leaves a gap — regressions introduced late, or bad data slipping through right after launch.

2Approach

Built two complementary gates: a pre-release tool comparing candidate builds against production metrics, and alpha testing — owned outright by my team — auditing every new model/feature for data-quality issues right after release.

3Outcome

Regressions caught pre-release; production data validated for integrity before it's ever used in a real business decision.

Model lifecycle governance & cost optimization

$1M+/yr

1Problem

Legacy models, features, and datasets accumulate indefinitely without a retirement process, quietly driving up infrastructure cost.

2Approach

Led the retirement and optimization of legacy models, features, and datasets, instituting governance discipline over lifecycle decisions instead of letting them run by default.

3Outcome

Delivered more than $1M in annual infrastructure and operational cost savings.

Agentic AI evaluation orchestrator

49/49 tests · 2 models

1Problem

Most "agentic AI" demos either check output against a fixed rubric with no real model-driven autonomy, or wrap a single LLM call and call it agentic with no real evaluation underneath. Neither earns the word.

2Approach

Built four evaluation tools (golden-dataset comparison, groundedness checking, LLM-as-judge, drift detection), each its own MCP server, then an orchestrator that lets the model itself decide which tools to call and when to stop — with the final approve/escalate verdict computed by tested, deterministic policy code, not the model's own opinion. Runs on Llama 3.1 (local, via Ollama) or Google Gemini behind one provider interface, with gate thresholds set per model from measured reliability. Wired into a CI/CD pipeline with a genuine human-approval gate.

3Outcome

Verified live, not just written: the model correctly stopped after one decisive tool call on a hallucinated answer, and — the sharpest result — the governed policy correctly overrode the model's own wrong "I'd recommend approving" when two tool calls had actually failed. The human-approval gate was proven end-to-end with a real reviewer click on live GitHub Actions. Measured on a second model, Gemini, the same policy got every verdict right even though its LLM judge rated a hallucination 9/10 — confirming why the final verdict stays in code.
