Case studies

Systems I designed and own at PayPal — described at the architecture level, without proprietary code or internal specifics.

AI-powered code review at scale

hours → minutes

1Problem

Manual PR review was a bottleneck, and a generic LLM reviewer wasn't useful across very different repos: on SQL repos it raised false critical alarms.

2Approach

Each repo gets a skill an LLM writes from its commit history. Every PR's diff is reviewed with that skill, and structured findings land as PR comments.

3Outcome

Review effort went from hours to minutes, the false critical alarms disappeared, and leadership dashboards track review quality and adoption.

GenAI test generation with a governed RAG layer

+80% coverage

1Problem

About 100 features shipped every week, with only one or two days to add tests, so only a handful could be covered. The constraint was scale, not speed.

2Approach

GPT-4 generates tests from a requirement or an OpenAPI spec, grounded by examples retrieved from each team's own tests, tagged by language and framework.

3Outcome

Generated tests for every weekly feature instead of a handful, lifting coverage 80% and cutting manual testing effort 40%.

Two-sided AI quality gates — before and after release

pre + post release

1Problem

Catching quality issues at only one point in the lifecycle leaves a gap — regressions introduced late, or bad data slipping through right after launch.

2Approach

A pre-release tool computes production's own metrics on the candidate build; after release, my team audits every new model and feature for bad data.

3Outcome

Regressions caught before launch; production data validated before it's ever used in a real business decision.

Model lifecycle governance & cost optimization

$1M+/yr

1Problem

Legacy models, features, and datasets accumulate indefinitely without a retirement process, quietly driving up infrastructure cost.

2Approach

Led the retirement and optimization of legacy models, features, and datasets, instituting governance over lifecycle decisions instead of letting them run by default.

3Outcome

More than $1M in annual infrastructure and operational cost savings.

Agentic AI evaluation orchestrator

101 tests · 105 labeled answers

1Problem

Most "agentic AI" demos either check output against a fixed rubric with no real autonomy, or wrap one LLM call and call it agentic. Neither earns the word.

2Approach

The model chooses which evaluation tools to call, each its own MCP server; tested, deterministic policy code makes the verdict, with a real human-approval gate.

3Outcome

Measured against 60 blind human-labeled answers on Llama 3.1 and Gemini, and hardened against prompt injection in the answers it evaluates.

Prompt injection: marking the answer as data in the prompt fully protected Gemini but made Llama worse, so the defenses that matter sit outside the model: code supplies the tools' inputs, and every answer is screened first. On 29 red-team attacks in 7 styles, the rule check alone caught 24% (only the crude ones). Adding an LLM classifier as a second signal raised that to 81% on Llama and 100% on Gemini, with no genuine false alarms on 124 normal answers. The classifier can only add escalations; it never approves.
Review load: at a realistic 5% bad-answer rate, about a quarter of live answers would go to a human, mostly because the groundedness check flagged good answers. A claim-by-claim version, scored on questions held out from its design, cut Gemini's false alarms from 14% to 2% with every bad answer still caught, shrinking the projected review queue from about 26% to 8% (closer to 16% on a fresh set built to be heavy on borderline inferences). On Llama the same change halved false alarms on the design questions and quadrupled them on the held-out ones, so it ships for Gemini only.
Fresh answers: every gate was chosen on the same 60 answers it was scored on, so 45 new answers were written and labeled blind afterwards. The cautious OR rule held on both models (93% and 100% of bad answers caught), the stricter AND rule again let about 40% through, and a threshold that looked better on the original 60 didn't hold up, so it wasn't adopted.
Repeatability: every check was re-run five times on the same answers, with temperature pinned to 0. The final verdict still changed on 12% of answers for Llama and 10% for Gemini, always on borderline cases, and a single run's catch rate ranged from 91% to 97%. Raising the temperature to 0.7 doubled the flips. Escalating every answer whose runs disagreed caught at most one more bad answer while sending more good ones to a human, so the gate stays one run, and each number above is read as one sample.
